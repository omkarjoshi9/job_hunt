## Known gaps and limitations of this documentation

* **Compact entries are not full walkthroughs.** Trivial helpers (one-liners, `__init__` methods that only store arguments, small row/attribute accessors) get a location, signature and two or three sentences, not the numbered step-by-step. Complex functions (for example `upsert_job`, `collect.run`, `hard_filter`, `score._score_batch`, `rank.select_diverse`, `bot._handle_callback`) have full walkthroughs.
* **Research scripts are summarised.** `scripts/probe_ats_tokens.py` and `probe_ats_tokens_wave2.py` carry large hand-curated data dictionaries (`LEVER_NAMES`, `ASHBY_NAMES`, `WORKABLE_NOTABLE`, `WAVE2`) that are described, not enumerated, and the scripts have no tests.
* **Tests are mapped, not walked.** The 62 test files are listed with what each covers and pins, and the helpers/fakes are documented; individual test bodies in the largest files (`test_hard_filter`, `test_sheet`, `test_legitimacy`, `test_priors`, `test_bot`) were summarised from names and spot reads.
* **Not exercised live.** Postgres code paths (placeholder rewriting, `RETURNING`, constraint migration), real OpenRouter and Telegram HTTP, Google Sheets, and browser-based portals were documented from the code and offline runs only. Statements about vendor behaviour (which ATS redirect on a bad slug, BambooHR payload shape) are marked as inferred in the relevant pages.
* **Data and generated files.** `data/*.tsv` are described (columns, sources, row counts, readers) but not reproduced. `src/jobdigest.egg-info/` is generated and ignored. `.cursor/plans/` holds stale planning notes and is not documented except as a drift warning in the infra pages.
* **Line numbers drift.** `path:line` references are exact for the documented working tree; the function name is the stable identifier. `check_docs.py` re-verifies every `Location` line.
* **Examples use the example profile.** `config/profile.yaml` is not in the repository, so outputs that depend on the profile were produced with `config/profile.example.yaml` (`min_yoe_reject` 3, empty `top_companies`).
* **Mermaid** diagrams are syntax-checked by the real parser; the parser does not check that a diagram is *semantically* right, which was verified by hand against the code when each diagram was written.
